## 1. Опис документної моделі та початкового наповнення

Для дослідження документо-орієнтованого підходу NoSQL спроєктовано нереляційну базу даних `library`, яка замість жорстких таблиць і зовнішніх ключів використовує денормалізовані BSON-документи з вкладеними об'єктами, масивами та вбудованими структурами.

### Колекції бази даних:
1. **`books` (16 документів):** каталог літератури з вкладеними масивами тегів-жанрів (`genres: [...]`), відгуків читачів (`ratings: [{ user, score, date }]`), числовими полями сторінок, ціни, наявності та посиланням на ідентифікатор автора `author_id`.
2. **`authors` (10 документів):** класики української літератури (Шевченко, Українка, Франко, Коцюбинський та ін.) із вкладеним документом біографії (`biography: { birth_place, education, era }`) та масивом нагород.
3. **`users` (10 документів):** читачі та бібліотекарі з масивом позичених книг (`borrowed_books: [...]`) та масивом літературних уподобань.
4. **`locations` (5 документів):** мережа філій бібліотеки у форматі **GeoJSON** (`location: { type: "Point", coordinates: [lng, lat] }`) для геопросторових запитів.
5. **`book_history`:** спеціалізована колекція журналу версіонування документів для фіксації повних зліпків стану до змін.

## 2. Базові операції CRUD (Рівень 1)

SQL-еквіваленти у документному середовищі реалізовано через API `mongosh` у файлі [scripts/02_basic_crud.js](file:///home/th0truth/code/Learn/college/sql-labs/lab06/scripts/02_basic_crud.js).

### 2.1. Створення документів (Create)
* **Вставка одного документа (`insertOne`):**
  ```javascript
  db.books.insertOne({
    title: "Сонячна машина",
    author: "Володимир Винниченко",
    publication_year: NumberInt(1928),
    pages: NumberInt(640),
    price: 450.00,
    isbn: "978-966-03-9999-1",
    genres: ["наукова фантастика", "соціальний роман", "утопія"],
    available: true,
    stock_quantity: NumberInt(8),
    borrowed_count: NumberInt(15)
  });
  ```
* **Вставка багатьох документів (`insertMany`):** пакетне додавання масиву документів за один мережевий запит до сервера.

### 2.2. Пошук та фільтрація (Read)
* **Рівність та діапазони (`$gte`, `$lte`):**
  ```javascript
  db.books.find(
    { pages: { $gte: 150, $lte: 350 } },
    { title: 1, author: 1, pages: 1, _id: 0 }
  );
  ```
* **Логічні оператори (`$or`, `$in`):**
  ```javascript
  db.books.find({
    $or: [
      { genres: "роман" },
      { author: "Василь Стефаник" }
    ]
  });
  ```
* **Регулярні вирази (`$regex`):** пошук видань, що містять у назві корені слів без урахування регістру:
  ```javascript
  db.books.find({ title: { $regex: /пісня|тіні/i } });
  ```
* **Проєкція та сортування:** вибірка лише необхідних полів (економія пам'яті та мережевого трафіку) з упорядкуванням `sort({ price: -1 }).limit(3)`.

### 2.3. Модифікація документів (Update)
* `$set` — оновлення скалярних полів (`price: 420.00`).
* `$push` — атомарне додавання нового відгуку до вкладеного масиву `ratings` без перезапису всього масиву.
* `$inc` — атомарний інкремент лічильника позичень (`borrowed_count: 1`) та декремент залишку на складі (`stock_quantity: -1`).
* `updateMany` — масова модифікація всіх книг XIX століття (`publication_year < 1900`).
* `replaceOne` — повна заміна тіла документа зі збереженням незмінного ідентифікатора `_id`.

### 2.4. Видалення документів (Delete)
* `deleteOne` — видалення єдиного цільового документа.
* `deleteMany` — безпечне видалення службових документів за критерієм `{ is_temporary: true }`.

## 3. Індексування та аналіз продуктивності (EXPLAIN)

У скрипті [scripts/03_indexes_and_performance.js](file:///home/th0truth/code/Learn/college/sql-labs/lab06/scripts/03_indexes_and_performance.js) створено 3 типи індексів:
1. **Простий B-Tree індекс:** `db.books.createIndex({ author: 1 })`.
2. **Складений (Compound) індекс:** `db.books.createIndex({ author: 1, publication_year: -1 })`.
3. **Унікальний індекс:** `db.books.createIndex({ isbn: 1 }, { unique: true })`.

### 3.1. Порівняння планів виконання запитів (`explain("executionStats")`)

| Параметр запиту | План виконання ДО індексації | План виконання ПІСЛЯ індексації | Ефект оптимізації |
| :--- | :---: | :---: | :---: |
| **Етап плану (Execution Stage)** | `COLLSCAN` (Повне сканування) | `FETCH` $\rightarrow$ `IXSCAN` (Індексне сканування) | Прямий доступ до B-Tree сторінок |
| **Перевірено документів (totalDocsExamined)** | **16** (100% колекції) | **2** (тільки відповідні) | **Скорочення навантаження на 87.5%** |
| **Зчитано ключів індексу (totalKeysExamined)** | 0 | 2 | Оптимізатор не читає зайві дані |
| **Сортування результату (Sort Stage)** | `SORT` (Сортування в RAM) | Відсутній (використано порядок B-Tree) | Усунено навантаження на CPU та RAM |

> **Захист від дублікатів:** При спробі вставки дубліката `isbn: "978-966-03-8201-1"` унікальний індекс генерує помилку `E11000 duplicate key error collection`, що гарантує цілісність даних на рівні ядра СУБД.

## 4. Агрегаційні конвеєри (Aggregation Pipelines — Рівень 2)

Скрипт [scripts/04_aggregation_pipelines.js](file:///home/th0truth/code/Learn/college/sql-labs/lab06/scripts/04_aggregation_pipelines.js) демонструє обробку даних через етапи `$match`, `$unwind`, `$group`, `$project`, `$sort`:

### 4.1. Розгортання масивів жанрів та підрахунок частоти
```javascript
db.books.aggregate([
  { $unwind: "$genres" },
  {
    $group: {
      _id: "$genres",
      total_books: { $sum: 1 },
      avg_price: { $avg: "$price" },
      titles: { $push: "$title" }
    }
  },
  { $sort: { total_books: -1 } }
]);
```
*Результат:* визначено найпопулярніші жанри фонду — *поезія* (3 книги, середня ціна 206.67 грн), *психологічна новела* (3 книги), *романтизм* (3 книги).

### 4.2. Обчислення віку літератури та групування за століттями
Використано математичні оператори `$divide` та `$ceil`:
```javascript
db.books.aggregate([
  {
    $project: {
      title: 1, author: 1, publication_year: 1,
      century: { $ceil: { $divide: ["$publication_year", 100] } }
    }
  },
  {
    $group: {
      _id: "$century",
      count: { $sum: 1 },
      authors: { $addToSet: "$author" }
    }
  },
  { $sort: { _id: 1 } }
]);
```
*Результат:* 8 книг XIX ст. (Шевченко, Франко, Стефаник, Квітка-Основ'яненко, Мирний) та 8 книг XX ст. (Винниченко, Довженко, Хвильовий, Підмогильний, Українка, Коцюбинський).

### 4.3. Оцінка фінансового еквівалента складських запасів
Обчислення сумарної вартості залишків за кожним жанром:
```javascript
{ $group: { _id: "$genres", total_value: { $sum: { $multiply: ["$price", "$stock_quantity"] } } } }
```
*Результат:* Лідери за складською вартістю — *романтизм* (17 900 грн), *поезія* (12 140 грн), *модернізм* (10 750 грн).

## 5. Об'єднання колекцій, представлення та текстовий пошук (Рівень 2)

SQL-код та конвеєри реалізовано у [scripts/05_lookup_and_views.js](file:///home/th0truth/code/Learn/college/sql-labs/lab06/scripts/05_lookup_and_views.js).

### 5.1. Оператор `$lookup` (Аналог SQL LEFT OUTER JOIN)
MongoDB виконує підтягування документа автора з колекції `authors` за зовнішнім посиланням `author_id`:
```javascript
db.books.aggregate([
  {
    $lookup: {
      from: "authors",
      localField: "author_id",
      foreignField: "_id",
      as: "author_info"
    }
  },
  { $unwind: "$author_info" },
  {
    $project: {
      title: 1,
      author_name: "$author_info.name",
      era: "$author_info.biography.era",
      birth_place: "$author_info.biography.birth_place",
      price: 1
    }
  }
]);
```

### 5.2. Створення представлення (`db.createView`)
Створено віртуальне представлення тільки для читання `available_books`, яке автоматично фільтрує лише доступні книги та розраховує дисконтну ціну для членів клубу (`club_price` зі знижкою 10%):
```javascript
db.createView("available_books", "books", [
  { $match: { available: true } },
  {
    $project: {
      title: 1, author: 1, publication_year: 1,
      regular_price: "$price",
      club_price: { $round: [{ $multiply: ["$price", 0.90] }, 2] },
      stock_quantity: 1
    }
  }
]);
```

### 5.3. Повнотекстовий індекс та пошук релевантності (`$text`)
Створено текстовий індекс `idx_books_text_search` з параметром `default_language: "none"`, що вимикає англійські стоп-слова та запобігає спотворенню українських слів:
```javascript
db.books.createIndex(
  { title: "text", description: "text" },
  { default_language: "none", name: "idx_books_text_search" }
);

// Пошук із сортуванням за оцінкою релевантності (textScore)
db.books.find(
  { $text: { $search: "кохання Карпатських" } },
  { title: 1, author: 1, score: { $meta: "textScore" } }
).sort({ score: { $meta: "textScore" } });
```
*Результат:* книга «Тіні забутих предків» отримала найвищий бал релевантності (**1.08**), оскільки містить обидва шукані терміни в описі.

## 6. Творче розширення (Рівень 3)

Реалізація у файлі [scripts/06_advanced_level3.js](file:///home/th0truth/code/Learn/college/sql-labs/lab06/scripts/06_advanced_level3.js).

### 6.1. Декларативна валідація схеми (JSON Schema)
Через команду `collMod` визначено суворі правила валідації на рівні колекції:
```javascript
db.runCommand({
  collMod: "books",
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["title", "author", "publication_year", "isbn", "available"],
      properties: {
        title: { bsonType: "string", minLength: 1, maxLength: 200 },
        author: { bsonType: "string", minLength: 2 },
        publication_year: { bsonType: "int", minimum: 1000, maximum: 2100 },
        pages: { bsonType: "int", minimum: 1 },
        isbn: { bsonType: "string", pattern: "^978-\\d{1,5}-\\d{1,7}-\\d{1,7}-\\d{1}$" },
        available: { bsonType: "bool" }
      }
    }
  },
  validationLevel: "strict",
  validationAction: "error"
});
```
* **Тест відхилення:** Спроба вставити книгу з роком `3050` та некоректним ISBN миттєво відхилена ядром MongoDB:
  ```text
  MongoServerError: Document failed validation
  ```

### 6.2. Геопросторовий індекс (`2dsphere`) та запит найближчих об'єктів (`$near`)
Для філій бібліотеки створено геоіндекс на основі моделі сферичної геометрії Землі (WGS84):
```javascript
db.locations.createIndex({ location: "2dsphere" });

// Пошук філій у радіусі 5 км від Хрещатика [30.5238, 50.4471]
db.locations.find({
  location: {
    $near: {
      $geometry: { type: "Point", coordinates: [30.5238, 50.4471] },
      $maxDistance: 5000
    }
  }
});
```
*Результат:* Запит автоматично ранжував 3 київські філії за реальною фізичною відстанню (Шевченківський зал $\rightarrow$ Подільська книгозбірня $\rightarrow$ Центральна міська бібліотека), відкинувши філії у Львові та Луцьку.

### 6.3. Система версіонування документів (Audit & History Tracking)
Створено архітектурний патерн **Document Versioning**:
1. Кожен документ містить цілочисельну версію `version` та мітку `updated_at`.
2. Перед внесенням будь-яких змін функція `updateBookWithVersioning` формує незмінний зліпок поточного стану книги у колекції `book_history`.
3. Основний документ оновлюється через атомарний `$inc: { version: 1 }`.
*Результат тесту:* Книга «Сад Гетсиманський» послідовно пройшла версії v1 $\rightarrow$ v2 $\rightarrow$ v3 із збереженням автора змін (`changed_by`), міток часу та дельти модифікацій.

## 8. Порівняльний аналіз: Реляційний (PostgreSQL) vs Документний (MongoDB) підходи

| Критерій порівняння | Реляційна модель (PostgreSQL) | Документна модель (MongoDB) |
| :--- | :--- | :--- |
| **Одиниця зберігання** | Рядок (Tuple) у таблиці фіксованої схеми | Документ BSON у динамічній колекції |
| **Нормалізація даних** | Сувора 3-тя нормальна форма (розділення сутностей) | Денормалізація, вкладені об'єкти та масиви |
| **Зв'язки між сутностями** | Первинні / зовнішні ключі (`FOREIGN KEY`) + `JOIN` | Вбудовані документи (Embedded) або посилання (`$lookup`) |
| **Гнучкість структури** | Потребує міграцій (`ALTER TABLE DDL`) | Гнучка схема, поліморфні документи, валідація JSON Schema |
| **Цілісність транзакцій** | Повна підтримка ACID на рівні всієї транзакції | ACID гарантується на рівні одного документа (підтримка транзакцій для Replica Set) |
| **Швидкодія вибірки** | Витрати на операції з'єднання багатьох таблиць | Миттєве читання повного агрегата за 1 операцію I/O |
| **Масштабованість** | Переважно вертикальна (Scale-Up) | Природна горизонтальна (Sharding / Scale-Out) |
| **Найкраще застосування** | Фінансові системи, ERP, суворий реляційний облік | Каталоги товарів, аналітика, CMS, IoT, високонавантажені сервіси |

## 10. Відповіді на контрольні запитання

### 1. У чому полягають основні відмінності між реляційними та документо-орієнтованими базами даних? Коли доцільно використовувати кожен підхід?
* **Реляційні СУБД (PostgreSQL, MySQL):** зберігають дані у двовимірних таблицях із жорсткою схемою, вимагають нормалізації (1НФ–3НФ) для уникнення дублювання та покладаються на операції `JOIN`. Забезпечують суворі гарантії ACID. Їх доцільно обирати для систем із високими вимогами до фінансової цілісності, складними транзакціями та стабільними структурами сутностей.
* **Документо-орієнтовані СУБД (MongoDB):** зберігають дані як самодостатні ієрархічні документи (BSON/JSON), дозволяють поліморфізм (різні документи в одній колекції можуть мати різний набір полів) та підтримують горизонтальне масштабування (шардинг) «з коробки». Їх доцільно обирати при динамічних вимогах до структури даних, швидкій розробці, високому навантаженні на читання/запис агрегованих об'єктів (каталоги, системи реального часу, профілі користувачів, IoT).

### 2. Що таке BSON і чим він відрізняється від JSON? Які переваги надає використання BSON у MongoDB?
**BSON (Binary JSON)** — це двійковий формат серіалізації документів, що використовується в MongoDB для зберігання та мережевої передачі даних.
* **Відмінності від JSON:**
  1. *Двійкове кодування:* містить префікси довжини та типи полів, що дозволяє СУБД швидко пропускати непотрібні поля без парсингу всього тексту (швидка навігація).
  2. *Розширені типи даних:* на відміну від базового JSON (який має лише string, number, boolean, null, array, object), BSON підтримує `ObjectId`, `ISODate`, 64-бітні цілі числа (`int64`), `Decimal128` (для фінансів), двійкові дані (`BinData`), регулярні вирази тощо.
* **Переваги:** висока швидкість парсингу/серіалізації, підтримка індексації двійкових структур та збереження точних типів числових і часових даних.

### 3. Поясніть концепцію денормалізації в контексті NoSQL баз даних. Які переваги та недоліки цього підходу?
**Денормалізація** — це стратегія моделювання даних, за якої пов'язані дані зберігаються безпосередньо всередині одного документа (через вкладені об'єкти або масиви), замість їх винесення в окремі колекції.
* **Переваги:**
  - *Максимальна продуктивність читання:* весь агрегат (наприклад, книга разом із рецензіями та авторами) зчитується з диска за одне звернення без `JOIN`.
  - *Атомарність:* будь-яка зміна всередині одного документа гарантовано атомарна без необхідності розподілених транзакцій.
* **Недоліки:**
  - *Дублювання даних:* якщо дані автора повторюються в сотнях книг, їх зміна вимагає масового оновлення.
  - *Зростання розміру документів:* обмеження розміру документа в MongoDB становить 16 МБ (BSON Document Size Limit).

### 4. Як працює агрегаційний pipeline в MongoDB? Опишіть основні етапи та їх призначення.
Агрегаційний pipeline — це конвеєр обробки даних за принципом UNIX-пайпів: колекція документів проходить послідовно через серію етапів (stages), де кожен етап приймає потік документів, трансформує його та передає наступному етапу.
* **Основні етапи:**
  - `$match` — фільтрація документів за умовами (використовує індекси, розміщується на початку конвеєра).
  - `$unwind` — деконструює масив у документі, створюючи окремий документ для кожного елемента масиву.
  - `$group` — групує документи за вказаним ключем `_id` та обчислює агрегатні вирази (`$sum`, `$avg`, `$min`, `$max`, `$push`, `$addToSet`).
  - `$project` — змінює структуру документа, перейменовує поля, створює обчислювані значення.
  - `$sort`, `$limit`, `$skip` — сортування, обмеження вибірки та пагінація.
  - `$lookup` — виконання лівого зовнішнього з'єднання з іншою колекцією.

### 5. Що таке індекси в MongoDB і як вони впливають на продуктивність запитів? Які типи індексів підтримує MongoDB?
**Індекс** у MongoDB — це спеціальна структура даних (B-Tree), яка зберігає невелику частину даних колекції у впорядкованому вигляді для швидкого пошуку.
* **Вплив:** Замість послідовного перегляду всіх документів колекції (`COLLSCAN`), планувальник використовує пошук за B-Tree деревом (`IXSCAN`), що знижує алгоритмічну складність із $O(N)$ до $O(\log N)$. При цьому індекси уповільнюють операції вставки/оновлення та потребують оперативної пам'яті (RAM).
* **Типи індексів:**
  1. *Single Field* — простий індекс по одному полю.
  2. *Compound* — складений індекс по декількох полях з урахуванням порядку та напрямку (1 / -1).
  3. *Multikey* — індекс для масивів (створює ключ для кожного елемента масиву).
  4. *Geospatial* (`2dsphere`, `2d`) — для координат і географічних обчислень.
  5. *Text* — для повнотекстового пошуку за словами.
  6. *Hashed* — хеш-індекс для шардингу.
  7. *TTL (Time-To-Live)* — автоматичне видалення документів після закінчення терміну дії.

### 6. Поясніть різницю між операторами updateOne, updateMany та replaceOne. Коли використовувати кожен з них?
* `updateOne(filter, update, options)`: оновлює **перший знайдений документ**, що відповідає фільтру. Вимагає операторів оновлення (`$set`, `$inc`, `$push` тощо). Використовується для точкових модифікацій одного запису за унікальним ідентифікатором або чергою.
* `updateMany(filter, update, options)`: оновлює **всі документи**, які задовольняють умову фільтра. Застосовується для масових регламентних змін (наприклад, зміна категорії всім книгам до 1900 року).
* `replaceOne(filter, replacement, options)`: **повністю перезаписує** перший знайдений документ новим переданим об'єктом (за винятком незмінного поля `_id`). Застосовується, коли потрібно зберегти оновлений стан доменного об'єкта цілком без окремих `$set` виразів.

### 7. Що таке валідація схеми в MongoDB і як вона реалізується через JSON Schema?
Валідація схеми дозволяє поєднати гнучкість NoSQL із гарантіями цілісності структури на рівні СУБД. Вона запобігає появі пошкоджених документів, некоректних типів даних та відсутності критичних полів.
* **Реалізація:** Задається при створенні колекції (`createCollection`) або модифікації (`collMod`) за допомогою ключового слова `$jsonSchema`.
* **Параметри:**
  - `bsonType` — перевірка типів BSON (`string`, `int`, `double`, `bool`, `array`, `object`).
  - `required` — перелік обов'язкових полів.
  - `minimum`, `maximum` — числові діапазони.
  - `pattern` — регулярні вирази для текстових полів (наприклад, формат ISBN або email).
  - `validationLevel` (`strict` / `moderate`) та `validationAction` (`error` / `warn`).

### 8. Як реалізувати зв'язки між документами в MongoDB? Порівняйте підходи з вбудованими документами та посиланнями.
У MongoDB зв'язки реалізуються двома способами:
1. **Вбудовування (Embedding / Denormalization):** вкладення об'єкта або масиву об'єктів усередину батьківського документа.
   - *Переваги:* швидкі вибірки без об'єднань, атомарні оновлення.
   - *Використовується:* для зв'язків 1:1 або 1:Few (наприклад, адреси користувача, розділи книги, відгуки).
2. **Посилання (Referencing / Normalization):** збереження `_id` зв'язаного документа з подальшим з'єднанням через `$lookup` або на рівні клієнтського застосунку.
   - *Переваги:* відсутність дублювання при змінах, обхід ліміту 16 МБ.
   - *Використовується:* для зв'язків 1:Many (де записів дуже багато) та Many:Many (наприклад, автори та видавництва).

### 9. Що таке текстовий індекс і як він використовується для повнотекстового пошуку?
**Текстовий індекс (`text`)** — це спеціалізований індекс MongoDB, який підтримує пошук слів і фраз усередині текстових полів.
* **Принцип роботи:** При індексації текст токенізується (розбивається на слова), видаляються стоп-слова, і за наявності мовного аналізатора застосовується стемінг (приведення до кореневої форми).
* **Використання:** запит виконується через оператор `$text: { $search: "слова" }`.
* **Релевантність:** MongoDB генерує внутрішню оцінку релевантності (`textScore`), яка враховує вагу полів (`weights`) та частоту входження, дозволяючи сортувати результати за точністю збігу.

### 10. Опишіть стратегії масштабування MongoDB. Що таке sharding і реплікація?
* **Реплікація (Replication — Replica Set):**
  - Архітектура з одного первинного вузла (**Primary**) та кількох вторинних (**Secondary**).
  - *Призначення:* забезпечення **високої доступності (High Availability)**, відмовостійкості та захисту від апаратних збоїв. Усі операції запису надходять на Primary і через журнал операцій `oplog` асинхронно копіюються на Secondary. При виході з ладу Primary відбувається автоматичне голосування (Heartbeat / Election) для обрання нового лідера.
* **Шардинг (Sharding — Horizontal Partitioning):**
  - Розподіл даних великої колекції між кількома окремими серверами (шардами) за спеціальним ключем шардингу (**Shard Key**).
  - *Призначення:* забезпечення **горизонтального масштабування (Scale-Out)**, коли обсяг даних або навантаження перевищує фізичні можливості одного сервера.
  - *Компоненти:* роутери `mongos` (маршрутизатори клієнтських запитів), сервери конфігурації `config servers` (зберігають метадані розподілу чанків) та безпосередньо шарди `shards` (кожен з яких є окремим Replica Set).
